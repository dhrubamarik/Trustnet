    Data Flow — Input to Output
    1. Ingestion. Review arrives with text, author, merchant, IP, device and payment token.
    2. Feature pipeline. Dual-space TF-IDF (word + char n-grams), entity-sharing counts, temporal velocity.
    3. Weak supervision. Eight heuristic labeling functions vote on an anomaly score.
    4. ML generalisation. Gradient Boosting learns non-linear risk from indirect signals.
    5. Graph linking. Union-find components join entities sharing hardware, payment, IP or copy — edges below weight 4.0 are dropped.
    6. Case rollup. Scattered bot accounts collapse into one urgent case with a human-readable triage action.
    Human-in-the-Loop Feedback
    1. Operator triage. Investigators inspect grouped cases, evidence lists and connection maps.
    2. Confirmed fraud. Freezing payouts and quarantining reviews converts a weak label into a ground-truth record.
    3. False-positive exception. Dismissed cases (household device sharing) emit exclusion rules that recalibrate thresholds.
    4. Continuous retraining. Ground-truth decisions update model weights against new fraud patterns.

    Protocol · 2 minutes

    1. Pick a ring type. Each simulates a different cross-signal pattern.
    2. Run it. Members are injected one at a time; the counter updates live.
    3. Check the verdict. The system either links them into one case or scatters them.
    PASS = all ring members in ONE case, tier at least the stated goal, in under 5 seconds.
    FAIL = members split across multiple cases, or tier below the goal.
